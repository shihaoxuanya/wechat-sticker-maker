# 一张图做微信表情包

把一张参考图变成高清静态表情、配套素材和可操作的上传清单。默认24款；用户指定的数量、画风、用字和角色优先。本 skill 负责制作、检查、驳回修正，上传由使用者自行完成。不要把本地检测通过说成官方审核通过。

## 按请求选择工作

- **新制作：** 读取参考图，执行下述流程。默认沿用参考角色画风；真人照片转绘时保留可辨识特征，不默认加入某个固定卡通角色的配饰。
- **检查已有包：** 先清点原文件与实际像素，建立项目配置，再运行 `check`；先指出问题，修正仅限用户授权范围。
- **驳回修正：** 读 [上传与修正](references/upload.md)，把驳回原因映射到实际文件，局部修正后重建、复查和打包。

## 制作流程

1. 读取参考图和已给出的需求。只在主体选择、意图或权利人信息确实无法确定时询问；不重复索取已经提供的信息。多人照片目标不清楚时先确定主体。检查用户需要的投稿类别，不能为了绕过类别要求而假称自绘或获得授权。
2. 用 [工具与配置](references/pipeline.md) 的 `init` 建立独立项目。保存角色说明、名字、逐款含义、画面文字和构图。先保留用户选题，再补充常用情绪；默认突出头脸，必要时保留身体。文字默认中文且按画风选择自然手写形式；无字要求优先。
3. 读取 [规范与证据](references/platform.md)。开始制作时明确目标参数；每次准备投稿前核对当前官方规则。附带的规则配置是**未核实的制作基线**，并非最新官方标准。官方无法访问时使用用户提供的官方截图，不绕过访问限制。缺失或冲突规则必须留为待核实，但可继续高清制作。
4. 按 [生成提示](references/generation.md) 使用内置 imagegen。存在 imagegen skill 时遵循它；本 skill 的参考文档也提供必要约束。逐款一张独立高清原图，先内部检查三个不同表情，再完成整套；不强制用户逐批批准。保存工具返回的原图到项目 `sources`，逐条记录实际提示词、来源、变体和选用理由。
5. 独立制作封面、横幅、聊天图标。图标默认50×50、透明、正面头部、无字、无额外装饰、无外圈白边。不能把带字表情或封面缩小充数。封面与横幅按各自规则设计，不套用图标构图。其它图中适合的爱心等效果不必因为图标要求而禁用。
6. 执行 `build`，保存原图、1024母图、使用PNG、缩略图和投稿副本。优先真实 alpha 和全色无损。不要从GIF截图造高清图，不要把上采样称作细节提升。抠图有颜色冲突时修正源图或提供保护蒙版，不全局删除某种颜色。脚本的背景检查提示只是线索。
7. 执行 `review-template`，实际查看每张成品、浅深背景总览、120px聊天尺寸以及50px原尺寸图标，填写与文件哈希绑定的视觉检查。文字、手部、身份、图标装饰不是仅凭像素能证明的；检查未完成就保留 `pending_visual`，不得批量写死通过。错字或装饰由图像生成流程定点修正。
8. 核实权利人、授权及平台实际要求的AI素材信息，填写证据和合规复核。不能自动编造“原创”、版权署名或授权。完成 `check` 和 `package`；未核实项存在时交付文件名带“草稿”的素材包，并精确说明待办。通过则称“已完成本地投稿前检查”，不要保证一次审核成功。

## 工具与交付约定

Python工具只做确定性的整理与检测，不调用收费API，也不代替 imagegen 生成插画。需要 Python 3.10+、Pillow、NumPy；优先使用当前环境已有运行时，依赖安装到独立环境。Windows、macOS、Linux均使用参数指定路径，不依赖作者电脑目录。

```text
python scripts/sticker_pipeline.py init --project <目录> --reference <图片> --name <角色名> --count 24
python scripts/sticker_pipeline.py build --project <目录>
python scripts/sticker_pipeline.py review-template --project <目录>
python scripts/sticker_pipeline.py check --project <目录>
python scripts/sticker_pipeline.py package --project <目录>
```

最终交付：网页预览、浅深背景检查图、主图与母图、缩略图、中文名称版、横幅/封面/独立图标、名称对应表、提示词、来源记录、检查报告、逐项上传清单和完整性验证过的ZIP。逐张修正后重新生成相关预览、报告及包；文件哈希改变会使旧视觉确认失效。

默认不制作动态表情、不操作上传页面、不扩大为账号注册或自动提交。用户明确新增需求时说明所需能力，保留其已经授权的范围。
